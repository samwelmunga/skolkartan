# Task: Prettier configuration and format scripts

## Description

Install and configure Prettier as the project's **sole** formatting authority, and add the two
scripts that drive it. This task does not touch ESLint — `E00_S02_T02` owns that side of the
boundary and is responsible for switching ESLint's stylistic rules off. The two tasks may run in
parallel; `E00_S02_T04` proves afterwards that they do not fight.

Assumes `E00_S01` has landed: `package.json` has scripts (`dev`, `build`, `start`, `typecheck`),
`tsconfig.json` exists, and there is a `src/` tree with `src/app/layout.tsx` and `src/app/page.tsx`.

### Dependency

Add `prettier` as a **devDependency** with a caret range (`^3.x`, whichever 3.x is current).
`package-lock.json` is committed, as per the policy set in `E00_S01`.

Add only this dependency and only the two scripts listed below. Do not add ESLint packages, Vitest
packages, or any other script — sibling tasks are adding theirs in parallel and every extra line
here is a merge conflict for someone else.

### `.prettierrc.json`

Create at the repository root with explicit values rather than relying on defaults, so the
configuration is readable rather than implied:

```json
{
  "printWidth": 100,
  "semi": true,
  "singleQuote": true,
  "trailingComma": "all",
  "arrowParens": "always",
  "endOfLine": "lf"
}
```

`endOfLine: "lf"` is deliberate: development happens on macOS and CI runs on Linux, and a CRLF
diff appearing only in CI is a wasted afternoon.

### `.prettierignore`

Create at the repository root. It must mirror `.gitignore` plus the two project-specific
exclusions, each with a stated reason:

```
# Build output and installed dependencies — not authored files.
node_modules/
.next/
out/

# Generated by npm; reformatting it produces enormous, meaningless diffs.
package-lock.json

# The scrum board is hand-maintained Markdown with deliberate line breaks, not source code.
project/
```

`src/` and `scripts/` are **not** excluded and must never be. (`scripts/` does not exist yet —
`E00_S03` creates it — but the ignore file must not pre-emptively exclude it.)

### Scripts

Add to `package.json`:

```json
"format": "prettier --write .",
"format:check": "prettier --check ."
```

`format` writes; `format:check` verifies and exits non-zero on any diff. Only `format:check` will
be registered as a CI check in `E00_S03` — **CI must never rewrite files**, because a pipeline
that edits the tree it is judging cannot be trusted to report on it.

### Formatting the existing tree

Run `npm run format` once over the tree that `E00_S01` left behind and commit the result, so that
`format:check` is green on a clean checkout from this point forward.

### Domain constraint

E00 is pure infrastructure. No kommun, skola, nyckeltal or data source may appear in any file this
task creates or modifies.

## Acceptance Criteria

- [ ] `prettier` appears in `devDependencies` in `package.json` with a caret range, and
      `package-lock.json` is updated and committed.
- [ ] `.prettierrc.json` exists at the repository root and sets `printWidth`, `semi`,
      `singleQuote`, `trailingComma`, `arrowParens` and `endOfLine` to the values listed above.
- [ ] `.prettierignore` exists at the repository root, excludes `node_modules/`, `.next/`, `out/`,
      `package-lock.json` and `project/`, and carries a comment stating the reason for each
      exclusion.
- [ ] `.prettierignore` does not exclude `src/` or `scripts/`.
- [ ] `package.json` contains exactly the scripts `format` and `format:check` with the commands
      given above, in addition to the scripts already present from `E00_S01`.
- [ ] `npm run format:check` exits zero on the clean tree.
- [ ] Deliberately misformatting a file under `src/` (for example collapsing indentation in
      `src/app/page.tsx`) makes `npm run format:check` exit non-zero and name that file in its
      output.
- [ ] `npm run format` rewrites that file and `npm run format:check` then exits zero again; the
      resulting tree is identical to the tree before the deliberate misformatting
      (`git status` is clean).
- [ ] `npm run format:check` does not report any file under `project/`.
- [ ] No file created or modified by this task references a kommun, skola, nyckeltal or data
      source.

## Definition of Done

- [ ] All acceptance criteria are met.
- [ ] `npm run format` run twice in succession produces no diff on the second run.
- [ ] `git status` is clean after running `npm run format` on the committed tree.
- [ ] `npm run typecheck` and `npm run build` still pass — formatting the tree broke nothing.
- [ ] No ESLint or Vitest package, config file or script was added by this task.
- [ ] The `format:check` script name is exactly `format:check`, so `E00_S03` can register it by
      name without renaming or rewrapping it.

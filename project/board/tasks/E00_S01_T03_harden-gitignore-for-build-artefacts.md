# Task: Harden .gitignore for build artefacts

## Description

Extend the existing `.gitignore` so that nothing a build produces can be accidentally committed,
and repair a defect currently in the file. This is a standalone edit to one file — it depends on
no other task and can run in parallel with `E00_S01_T01` and `E00_S01_T02`.

### The current file, verbatim

```
# macOS & Windows system files
.DS_Store
Thumbs.db
Desktop.ini

# Environment files
.env
.env.*
*.local

# Dependency directories
node_modules/
vendor/
.venv/
EOF
```

Two things are wrong with it:

1. **The trailing `EOF` line is a defect.** It is heredoc residue from however this file was
   generated, and it currently instructs git to ignore any path named `EOF`. Delete it.
2. It predates the application and covers no build output: `.next/`, `out/` and `*.tsbuildinfo`
   are all absent.

### Required result

Delete the stray `EOF` line and append a build-output section. Add `.env*.local` explicitly even
though `.env.*` and `*.local` already cover it, because the story names that exact pattern and an
ignore file is read by humans as documentation of what is generated:

```
# Environment files
.env
.env.*
.env*.local
*.local

# Next.js build output
.next/
out/
next-env.d.ts.timestamp

# TypeScript incremental build info
*.tsbuildinfo
```

`*.tsbuildinfo` is required because `tsconfig.json` sets `incremental: true` (see `E00_S01_T02`),
which makes `tsc --noEmit` write `tsconfig.tsbuildinfo` next to the config.

### What must NOT be ignored

- **`next-env.d.ts`** — this file is generated by Next.js but is **committed** and is referenced by
  `tsconfig.json`'s `include`. Adding it to `.gitignore` would break the type-check on a fresh
  clone. Make sure no pattern in the file matches it.
- `package-lock.json` — committed by policy (`E00_S01_T01`).
- Anything under `src/`, `scripts/`, `docs/` or `project/`.

### Scope

Edit `.gitignore` and nothing else. Do not touch `package.json`, `tsconfig.json` or any file under
`src/` — sibling tasks own those in parallel worktrees.

### Domain constraint

E00 is pure infrastructure. No kommun, skola, nyckeltal or data source may appear in this file.

## Acceptance Criteria

- [ ] The stray `EOF` line is gone; the last line of `.gitignore` is a real ignore pattern or a
      comment.
- [ ] `.gitignore` contains `.next/`, `out/`, `*.tsbuildinfo` and `.env*.local`.
- [ ] `git check-ignore -q .next/build-manifest.json` exits zero.
- [ ] `git check-ignore -q out/index.html` exits zero.
- [ ] `git check-ignore -q tsconfig.tsbuildinfo` exits zero.
- [ ] `git check-ignore -q .env.production.local` exits zero.
- [ ] `git check-ignore -q node_modules/next/package.json` exits zero.
- [ ] `git check-ignore -q next-env.d.ts` exits **non-zero** — the file is committed, not ignored.
- [ ] `git check-ignore -q package-lock.json` exits **non-zero**.
- [ ] `git check-ignore -q src/app/page.tsx` exits **non-zero**.
- [ ] `git check-ignore -q docs/index.md` and `git check-ignore -q scripts/ci/checks.ts` both exit
      **non-zero**, so the directories later stories create are not pre-emptively ignored.
- [ ] Every ignore section carries a comment heading saying what it covers.

## Definition of Done

- [ ] All acceptance criteria are met.
- [ ] The pre-existing entries (`.DS_Store`, `Thumbs.db`, `Desktop.ini`, `.env`, `.env.*`,
      `*.local`, `node_modules/`, `vendor/`, `.venv/`) are all still present — this task adds and
      repairs, it does not prune.
- [ ] `git status` reports no newly-ignored file that was previously tracked; running
      `git ls-files --ignored --exclude-standard -c` returns nothing.
- [ ] No file other than `.gitignore` was created or modified by this task.
- [ ] No kommun, skola, nyckeltal or data source is referenced in the file.

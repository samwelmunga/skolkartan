### Why each new rule is there

| Rule | Reason |
|---|---|
| `.env*.local` | Already covered transitively by `.env.*` and `*.local`, but the parent story names this exact pattern, and an ignore file is read by humans as documentation of what the toolchain generates. Being explicit costs one line and removes a guess. |
| `.next/` | Next.js writes its whole build here. Trailing slash so only a directory can match, never a stray file of that name. |
| `out/` | Static export target (`next export` / `output: 'export'`). Trailing slash for the same reason. |
| `next-env.d.ts.timestamp` | Transient marker written next to `next-env.d.ts` by the Next.js type plugin. Written as a literal filename, deliberately **not** as `next-env.d.ts*`, so it cannot swallow the committed `next-env.d.ts`. |
| `*.tsbuildinfo` | `tsconfig.json` sets `incremental: true` (E00_S01_T02), so `tsc --noEmit` drops `tsconfig.tsbuildinfo` beside the config on every typecheck run. |

Every section, old and new, carries a comment heading stating what it covers.

`next-env.d.ts` is the important one: it is generated by Next.js but committed, and
`tsconfig.json`'s `include` references it. Had it been ignored, type-check on a fresh clone would
break. It is not matched — `.env.*` matches only basenames beginning `.env.`, and
`next-env.d.ts.timestamp` is a literal, not a prefix glob.

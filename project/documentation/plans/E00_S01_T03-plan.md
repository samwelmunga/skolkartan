## Objective

Repair a defect in `.gitignore` (a stray literal `EOF` line left over from heredoc generation) and
extend the file so that nothing produced by the Next.js / TypeScript toolchain can be accidentally
committed. Exactly one file is edited: `/Users/samwelmunga/Desktop/Projects/skolkartan/.gitignore`.

## Current state

`.gitignore` as it exists today (15 lines):

```
# macOS & Windows system files
.DS_Store
Thumbs.db
Desktop.ini

# Environment files
.env
.env.*
*.local

# Dependency directories
node_modules/
vendor/
.venv/
EOF
```

Two defects:

1. Line 15 is a bare `EOF`. It is not an intentional rule — it is heredoc residue — and it silently
   instructs git to ignore any path named `EOF`.
2. The file predates the application. No build output is covered: `.next/`, `out/` and
   `*.tsbuildinfo` are all absent, and the story explicitly names `.env*.local`.

## Target state

```
# macOS & Windows system files
.DS_Store
Thumbs.db
Desktop.ini

# Environment files
.env
.env.*
.env*.local
*.local

# Dependency directories
node_modules/
vendor/
.venv/

# Next.js build output
.next/
out/
next-env.d.ts.timestamp

# TypeScript incremental build info
*.tsbuildinfo
```

### Rationale, rule by rule

| Rule | Why |
|---|---|
| `.env*.local` | Redundant against `.env.*` + `*.local`, but the story names this exact pattern and an ignore file is read by humans as documentation of what the toolchain generates. Explicit beats inferred. |
| `.next/` | Next.js build output directory. Trailing slash so only a directory matches. |
| `out/` | Output of `next export` / static export. Trailing slash for the same reason. |
| `next-env.d.ts.timestamp` | Transient sibling written by the Next.js type plugin. Matched literally so it cannot catch `next-env.d.ts` itself. |
| `*.tsbuildinfo` | `tsconfig.json` sets `incremental: true` (E00_S01_T02), so `tsc --noEmit` writes `tsconfig.tsbuildinfo` next to the config. |

### Must NOT be ignored

- `next-env.d.ts` — generated by Next.js but **committed**, and referenced by `tsconfig.json`'s
  `include`. Ignoring it would break type-check on a fresh clone. Verified: `.env.*` matches only
  basenames beginning `.env.`, and `next-env.d.ts` does not; `next-env.d.ts.timestamp` is a literal
  match, not a prefix glob.
- `package-lock.json` — committed by policy (E00_S01_T01).
- Anything under `src/`, `scripts/`, `docs/`, `project/`.

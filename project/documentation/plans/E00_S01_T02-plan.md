## The TypeScript 7 question

`E00_S01_T01` installed `typescript@7.0.2`, the **native** compiler, not `tsc` 5.x. The task file was
written before that was known, so every compiler option it mandates must be verified empirically
rather than assumed. The specific risk flagged in the `T01` handoff is `baseUrl`, which has been on a
deprecation path in recent TypeScript releases.

Verification approach, in order:

1. Enumerate the options the compiler actually accepts (`tsc --help --all`) and confirm each mandated
   option is present with the expected type — in particular `baseUrl`, `paths`, `strict`,
   `noUncheckedIndexedAccess`, `noImplicitOverride`, `forceConsistentCasingInFileNames`,
   `isolatedModules`, `moduleResolution: bundler`, `noEmit`, `incremental`, `jsx: preserve`.
2. Write the config exactly as the task specifies, then run `tsc --noEmit` and read the output for
   deprecation warnings or errors, not just the exit code.
3. Prove each strictness flag is *behaviourally* live, not merely accepted, by feeding the compiler a
   snippet that only fails when the flag is on. An option silently ignored by a new compiler
   implementation would still exit zero, so exit code alone is not evidence.
4. Prove the `@/*` alias resolves under both `tsc` and `next build` — the two resolvers are separate
   implementations and only agreeing on both is meaningful.

If an option is rejected, renamed or behaviourally inert, adapt (for `baseUrl` specifically: drop it
and keep `paths`, which resolves relative to the config file) and record the deviation in the
summary. No requirement is dropped silently, and `typescript.ignoreBuildErrors` is never used.

If TS 7 turns out to be incompatible with Next 16's type-checking altogether, the sanctioned fallback
from the `T01` handoff is to pin `typescript` to `^5` and refresh the lockfile. That would modify
`package.json`, which this task otherwise must not touch, so it is a last resort taken only with the
incompatibility demonstrated in the summary.

## Risks and mitigations

- **TS 7 silently ignores an option instead of rejecting it.** The most dangerous failure mode: the
  config looks right, exits zero, and enforces nothing. Mitigated by step 9 — each strictness flag is
  proven by a snippet that must fail.
- **`tsc` and Next disagree about the `@/*` alias.** Next 16 builds with Turbopack, whose resolver is
  independent of `tsc`'s. Mitigated by requiring both `typecheck` and `build` to resolve the imports.
- **`next build` rewrites `next-env.d.ts`.** Expected; the file is generated, must be committed, and
  must never be hand-edited. If a build regenerates it, the regenerated version is what stands.
- **`.next/types/**/*.ts` in `include` does not exist before the first build.** Harmless — `include`
  globs that match nothing are not an error as long as at least one other pattern matches. The first
  `typecheck` on a never-built tree is the case to watch.
- **Ambient Node 20.10.0.** Every command is run under `nvm use 24.18.0`; running on Node 20 produces
  misleading failures.
- **`npm run dev` is a long-running server.** Started in the background, probed over HTTP, and stopped
  explicitly so no stray process is left holding a port.

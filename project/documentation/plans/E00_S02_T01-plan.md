## Risks identified before writing anything

### R1 — `next-env.d.ts` will fight Prettier, and Next.js will win

`next-env.d.ts` is regenerated by `next build`/`next dev` with double-quoted imports. With
`singleQuote: true`, `npm run format` would rewrite it to single quotes; the next `npm run build`
would rewrite it straight back. The consequences chain directly into this task's own criteria:

- Definition of Done "`git status` is clean after running `npm run format` on the committed tree"
  would hold only until the next build.
- Acceptance criterion "`npm run format:check` exits zero on the clean tree" would flip to non-zero
  after any build — the exact CRLF-in-CI class of wasted afternoon that `endOfLine: "lf"` exists to
  prevent.
- `E00_S03` registers `format:check` as a CI check, and CI builds. The check would be permanently
  red through no fault of any author.

**Planned mitigation**: exclude `next-env.d.ts` in `.prettierignore` with a stated reason. This is
an addition to the list the task specifies, not a removal from it — the task requires the five
listed entries to be present, and does not forbid further deliberate, reasoned exclusions. It does
not touch `src/` or `scripts/`. To be verified empirically, not assumed: format the file, run
`next build`, and observe whether Next rewrites it.

### R2 — `.claude/` and `.agents/` are 256 tracked harness files

`prettier --write .` would reformat 124 Markdown files, 33 JSON files and the rest of the agent
harness in a single commit belonging to an infrastructure task about the application's toolchain.
That is a large, unreviewable diff in files this task has no mandate over, and the harness rewrites
them independently.

**Planned mitigation**: exclude both with a stated reason, on the same logic the task itself applies
to `project/` — hand-maintained, agent-owned, not application source.

### R3 — Prettier 3 reads `.gitignore` by default

Since 3.0 the default `--ignore-path` is `.gitignore` **and** `.prettierignore`. So build output is
already excluded once via git. `.prettierignore` still lists `node_modules/`, `.next/` and `out/`
explicitly, because the task requires those entries and because a config that is readable rather
than implied is the stated preference of this story. To be confirmed empirically rather than
trusted.

### R4 — files Prettier cannot parse

`.jenga-version`, `.nvmrc`, `*.sh`, `*.py`, `*.pyc`, `*.csv`, `board-index` have no Prettier parser.
Prettier skips unknown extensions when expanding a directory, so no `--ignore-unknown` flag should
be needed. To be confirmed.
